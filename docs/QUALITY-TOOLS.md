# Code-quality and refactoring tools

Snapshot from 18–19 October 2026; tool versions and findings are as of those dates.

## Recommendation

Combine duplication discovery with language-specific reachability checks, then justify each deletion or extraction against real callers and tests. Reduced LOC is an outcome, not sufficient evidence of improved design. This note records the primary-source research behind the quality checks. The tool runs and refactors that followed it are not part of this document.

The research assumed Rust/Clippy **1.94.0** and Node **20.20.1**. jscpd, Knip, cargo-machete and Ruff were provisioned at the pinned versions below in temporary directories; ast-grep was not needed. [`scripts/audit-code-quality.py`](../scripts/audit-code-quality.py) runs the resulting checks.

Use local reports. jscpd's optional semantic mode can download a large model or send code to an embedding endpoint: leave it off. Start with ordinary exact clones; normalized or near-miss matching is a later, noisier pass. [jscpd options](https://github.com/kucherenko/jscpd/blob/v5.4.1/docs/rust.md).

## Initial commands

```sh
export OVERTALK_QUALITY="$(mktemp -d /tmp/overtalk-quality.XXXXXX)"

timeout -k 5s 180s jscpd . --workers 3 \
  --format rust,python,javascript,jsx,typescript,tsx \
  --min-lines 10 --min-tokens 80 --reporters json --fail-on-empty \
  --ignore '**/vendor/**,**/target/**,**/node_modules/**,**/.next/**,**/out/**,**/dispatch.rs,**/web_dispatch.rs' \
  --output "$OVERTALK_QUALITY/duplicates"

(cd frontend && knip --reporter json --no-progress) \
  > "$OVERTALK_QUALITY/knip.json"

cargo machete --skip-target-dir . > "$OVERTALK_QUALITY/machete.txt"
CARGO_BUILD_JOBS=3 cargo clippy --locked --workspace --all-targets \
  --message-format=json > "$OVERTALK_QUALITY/clippy.json"

ruff check --no-cache --no-fix --select F401,F841 --output-format json \
  speech-worker scripts integrations evaluations \
  > "$OVERTALK_QUALITY/ruff.json"
```

Preserve nonzero exit statuses and parse errors. Record exclusions and analyzed-file counts. Triage vendored/generated findings separately; edit their generator or maintained patch rather than deleting generated output. Do not enable auto-removal. In particular, machete's `--with-metadata` invokes `cargo metadata --all-features` and may modify lockfiles; its `--fix` can remove false positives. [machete behavior](https://github.com/bnjbvr/cargo-machete/blob/v0.9.2/README.md).

## Reachability and refactoring checks

Knip's Next plugin recognizes App Router pages/layouts/routes and framework entry files. Its published Tauri plugin reads `beforeDevCommand`, `beforeBuildCommand` and `beforeBundleCommand`; it does not prove Rust IPC or Slint callback reachability. Inspect package scripts, tests, generated imports, public assets and dynamic imports before adding narrowly justified entries. Declaring every source file an entry would hide unused files. Resolve missing entries/imports before acting on cascading unused-export/dependency findings. [Next plugin](https://knip.dev/reference/plugins/next), [published plugin source](https://registry.npmjs.org/knip/-/knip-6.42.0.tgz), [issue handling](https://knip.dev/guides/handling-issues).

For Rust, inspect `cfg` branches, platform backends, build scripts, procedural macros, Tauri handler registration and generated dispatch. Do not interpret a Linux default-feature check as proof about Windows/macOS or every acceleration feature; indiscriminate `--all-features` is inappropriate for mutually incompatible backends. For Python, inspect `__all__`, `importlib`, registry side effects and CLI entry points. F841 fixes can alter behavior or comments; review them rather than enabling unsafe fixes. [Ruff F401](https://docs.astral.sh/ruff/rules/unused-import/), [F841](https://docs.astral.sh/ruff/rules/unused-variable/).

Slint needs direct review of component imports, exported properties, callbacks and Rust bindings. Keep its coverage gap explicit; treating `.slint` as Rust or plain text does not provide language-aware validation. Preserve the retained web interface and cross-platform code unless evidence establishes that the relevant behavior was intentionally retired.

## Skills, Astra and contributor guidance

Matt Pocock's [codebase-design skill](https://github.com/mattpocock/skills/blob/main/skills/engineering/codebase-design/SKILL.md) is the best default: concentrate behavior behind a small interface, choose a real seam, and avoid wrappers that merely relocate complexity. jscpd's optional [dry-refactoring skill](https://github.com/kucherenko/jscpd/blob/v5.4.1/skills/dry-refactoring/SKILL.md) usefully separates exact clones from noisier similarities and asks reviewers to preserve intentional boilerplate. No additional skill installation is needed for this pass.

OpenAI's **14 October** maintenance guidance describes Astra gathering evidence for deletions and explicitly warns that reflection and operational safeguards defeat simplistic unused-code analysis. Its **11 September** prompting guidance recommends concise skill descriptions, contextual documentation links, less repetitive AGENTS.md scaffolding and explicit completion criteria. These support an evidence-led workflow; they do not establish an optimal Astra setting for this repository. [Maintenance guidance](https://developers.openai.com/blog/maintaining-software-with-the-gpt-6-family), [Astra instructions guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra).

Keep contributor AGENTS.md rules concrete: native architecture and supported interfaces; authoritative generators; evidence required before deleting dynamic/platform code; behavior-preserving extraction; relevant test commands; protection of user data and machine settings. Link specialized documents when relevant rather than requiring every document before every edit. For each cleanup, record the caller evidence, changed behavior contract, affected checks and actual LOC/duplication delta. Prefer fewer concepts and clearer ownership over maximizing deleted lines.

## 19 October refresh: remaining review

The published latest versions remain jscpd **5.4.1**, Knip **6.42.0**, cargo-machete **0.9.2** and Ruff **0.17.1**; no upgrade is needed for this follow-up. Rechecked both official OpenAI articles: their guidance still supports evidence-backed cleanup and concise, contextual instructions, not a repository-specific Astra setting. [jscpd registry](https://registry.npmjs.org/jscpd/latest), [Knip registry](https://registry.npmjs.org/knip/latest), [machete releases](https://api.github.com/repos/bnjbvr/cargo-machete/releases/latest), [Ruff registry](https://pypi.org/pypi/ruff/json).

Useful additions to the existing checks, without changing their baseline:

- **Review export visibility.** At the start of this review, the [quality runner](../scripts/audit-code-quality.py) gated Knip files/dependencies/references without exports; a later audit added export/type checks. Run `knip --exports --reporter json --no-progress` from `frontend/` for the remaining export/type/member candidates. Use `--trace-export NAME` or `--trace-file FILE` to inspect graph evidence. A declaration used only within its own module may need its export removed, not its implementation deleted. These options are present in the [published 6.42.0 CLI source](https://registry.npmjs.org/knip/-/knip-6.42.0.tgz).
- **Distinguish test-only reachability.** Knip's `--production` can reveal code kept alive solely by tests. First inspect `--debug` entry/project lists: the current configuration has no explicit `!` production markers, while framework plugins contribute their own production entries. Configure intended production patterns and keep the ordinary run too; an unconfigured production report is not deletion evidence. [Production-mode semantics](https://knip.dev/features/production-mode).
- **Extend clone discovery selectively.** `--cross-formats js-ts` compares related JS/JSX/TS/TSX formats. For one promising module family, try a separate `--max-gap-lines 1` or `--similarity 0.9` report. These expose edited/structurally similar copies but increase false positives. Keep original roots, exclusions and thresholds for before/after exact-clone measurements; do not merge independent provider/platform policies merely because their shapes match. [Pinned jscpd options](https://github.com/kucherenko/jscpd/blob/v5.4.1/docs/rust.md).
- **Cover unpacked Python bindings.** F841 excludes assignments such as `used, unused = result`. An optional report-only Ruff run selecting **RUF059** covers that gap. Preserve evaluation and unpacking behavior; an underscore name may express intentional non-use without removing any computation. [F841 source](https://github.com/astral-sh/ruff/blob/0.17.1/crates/ruff_linter/src/rules/pyflakes/rules/unused_variable.rs), [RUF059](https://docs.astral.sh/ruff/rules/unused-unpacked-variable/).

This refresh performed research only; these additional runs are recommendations, not reported findings or completed validation.

## Deeper review: missing gates and structural checks

**Implemented gate: TypeScript unused declarations.** The initial review found `strict` enabled without either unused option. A later audit enabled both in `frontend/tsconfig.json`. The explicit command remains useful for a report without a cache write:

```sh
cd frontend
pnpm exec tsc --noEmit --incremental false \
  --noUnusedLocals --noUnusedParameters --pretty false
```

These options cover local declarations and parameters that an export graph cannot replace. Keep them in the normal typecheck to prevent recurrence. Preserve initializer side effects and callback contracts; underscore-prefixed parameters are exempt. Disabling incremental mode avoids changing the compiler's build-info cache during this exploratory run. This does not establish that exported APIs or dynamically read object properties are unused. [Unused locals](https://www.typescriptlang.org/tsconfig/noUnusedLocals.html), [unused parameters](https://www.typescriptlang.org/tsconfig/noUnusedParameters.html), [incremental cache](https://www.typescriptlang.org/tsconfig/incremental.html).

**Knip complements that gate.** A focused `knip --exports --include-entry-exports --reporter json --no-progress` can inspect exports normally hidden by entry status; retain framework-required exports even when no ordinary import exists. The `--exports` shorthand also includes namespace export checks that deliberately relax Knip's enumeration heuristic: inspect `Object.keys`, spreads and dynamic property access before removing members. Its member categories cover exported enums/namespaces, not arbitrary class methods. Compare ordinary and correctly configured production graphs; use tracing for individual candidates instead of interpreting a whole report as deletion permission. [Export caveats](https://knip.dev/guides/handling-issues#unused-exports), [issue categories](https://knip.dev/reference/issue-types), [CLI and tracing](https://knip.dev/reference/cli).

**Rust visibility needs explicit review.** The installed compiler's `rustc -W help` lists `unreachable-pub` as allowed by default; `-D warnings` alone does not enable it. A targeted report is `CARGO_BUILD_JOBS=3 cargo clippy --locked -p sonefold --lib --no-deps -- -W unreachable_pub`. It finds overbroad `pub` inside private module trees, but cannot identify unnecessary external APIs in the backend's many fully public modules. Check binary/helper consumers, integration tests, macro requirements and supported configurations before narrowing to `pub(crate)` or `pub(super)`. The newer `dead_code_pub_in_binary` entry in online documentation is absent from this installed compiler's lint list. [Lint semantics](https://doc.rust-lang.org/rustc/lints/listing/allowed-by-default.html#unreachable-pub), [visibility rules](https://doc.rust-lang.org/reference/visibility-and-privacy.html).

**Command extraction has a contract beyond compilation.** Tauri supports commands in private modules with module-qualified handler registrations while retaining the same bare IPC command name. The local [generator](../scripts/generate-native-dispatch.py) resolves unqualified registrations specifically from `lib.rs`, and qualified registrations by source-module paths. Therefore move registrations with definitions, preserve argument names and native exclusions, regenerate both adapters, and compare command names, argument keys and event inventory before/after. A useful generator regression gate is deterministic regeneration plus explicit contract comparison; matching command counts alone misses substitutions. Macro-generated visibility needs compilation checks rather than a blanket `pub` replacement. [Tauri module and argument conventions](https://v2.tauri.app/develop/calling-rust/#defining-commands-in-a-separate-module).

**Python structural duplicates need no new package.** For a bounded report, parse maintained Python sources without importing them and group substantial function bodies by `ast.dump(ast.Module(body=node.body, type_ignores=[]), include_attributes=False)`. Keep identifiers and literal values intact initially. This proposed method ignores formatting and source positions but is only candidate discovery: equal bodies can resolve names differently, and signatures, defaults, decorators, sync/async behavior and closures need separate comparison. Report parse failures; exclude vendored/generated sources and preserve the existing exact-token baseline. [Python 3.12 AST API](https://docs.python.org/3.12/library/ast.html#ast.dump).

The official Astra maintenance and prompting articles were rechecked for this deeper pass; the evidence and scope guidance above remains applicable. This research update claims no tool installation, scanner run or completed cleanup.

## 19 October follow-up: preserving semantics when sharing code

The earlier export, unused-variable and generator recommendations were implemented in a later audit. The useful next checks concern newly introduced coupling and behavior, rather than another identical scan.

- **Check import cycles after extraction.** Knip **6.42.0** supports `knip --cycles --reporter json --no-progress`; verified in its published package. Run from `frontend/` and compare cycles touching moved modules. Cycles are reported as warnings by default, so exit zero does not mean none exist; set `rules.cycles` to `error` only after reviewing the baseline. This checks runtime import relationships, not Rust/Python dependencies or semantic equivalence. [Published CLI](https://registry.npmjs.org/knip/-/knip-6.42.0.tgz), [cycle issue semantics](https://knip.dev/reference/issue-types).
- **Check side-effect imports explicitly.** `pnpm exec tsc --noEmit --incremental false --noUncheckedSideEffectImports --pretty false` catches unresolved bare imports that ordinary TypeScript checking can silently accept. Treat CSS/asset-loader declarations deliberately: a wildcard declaration permits the pattern but does not prove a file exists, so retain the production build. Moving a registration or singleton into a shared module also needs runtime review: `import type` disappears from emitted JavaScript and cannot execute initialization. [Compiler option](https://www.typescriptlang.org/tsconfig/noUncheckedSideEffectImports.html), [type-only imports](https://www.typescriptlang.org/docs/handbook/modules/reference.html#type-only-imports-and-exports).
- **Compare Rust resource lifetimes, not just bodies.** A shared helper can change when locks, transactions or cleanup guards drop. Keep an explicit before/after account of guard scopes and `.await` points when extracting recording, transfer or IPC logic. Tokio documents that `read_exact`/`write_all` are not cancellation-safe in a restarted `select!` loop, while cancelling a queued mutex acquisition loses its place. A compiler-clean extraction does not prove equivalent partial progress or cancellation behavior. Exercise these cases when the extraction changes them. [Drop scopes](https://doc.rust-lang.org/reference/destructors.html#drop-scopes), [Tokio cancellation safety](https://docs.rs/tokio/latest/tokio/macro.select.html#cancellation-safety).
- **Keep extraction tests independent of the implementation.** Share fixture construction when useful, but retain explicit expected outputs and caller-specific failure assertions instead of computing expectations with the new helper. For Python moves, patch the name where the caller looks it up; use `autospec=True` for replaced callable interfaces when appropriate. Ordinary unrestricted mocks can keep passing after an interface breaks. Existing behavior tests suffice for literal moves; changed ownership, ordering or errors warrant focused regression cases. [Python patch lookup](https://docs.python.org/3/library/unittest.mock.html#where-to-patch), [autospeccing](https://docs.python.org/3/library/unittest.mock.html#autospeccing).

Rechecked OpenAI's [maintenance guidance](https://developers.openai.com/blog/maintaining-software-with-the-gpt-6-family) and [Astra prompting guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra): prioritize benefit over added complexity and keep test instructions contextual. For a semantic duplicate, record the shared invariant and each intentional difference before choosing the interface. These recommendations are research findings; this follow-up ran no scanners or application tests.

## 19 October targeted follow-up: initialization and IndexedDB

**Choose initialization semantics explicitly.** An asynchronous check-then-create sequence can construct multiple managers if it releases the mutex before awaiting construction. `tokio::sync::OnceCell::get_or_try_init` coordinates a single successful initialization; failure, cancellation or panic allows another attempt. Its initializer must tolerate cancellation, and recursive initialization deadlocks. Use it for a manager whose identity remains fixed, not for model-selection or shutdown state that must be replaced. A Tokio mutex can instead serialize a replaceable lifecycle across awaits; a short synchronous mutex remains appropriate when no await is needed. These semantics were also checked in the locally cached Tokio **1.52.3** source. [OnceCell](https://docs.rs/tokio/latest/tokio/sync/struct.OnceCell.html#method.get_or_try_init), [mutex selection](https://docs.rs/tokio/latest/tokio/sync/struct.Mutex.html#which-kind-of-mutex-should-you-use).

**Test the race deterministically with existing Tokio.** Inject a local constructor for tests, count invocations, and pause it with a channel while several callers request the same manager. Assert one successful construction and shared `Arc` identity; separately test failure-then-retry and cancellation-then-retry. Coordinate events instead of sleeping, and avoid process-global cells that leak state between tests. The existing Tokio `full` feature and Rust test suite suffice; no nightly toolchain or GPU model load is needed. [Tokio oneshot channels](https://docs.rs/tokio/latest/tokio/sync/oneshot/index.html).

**A successful IndexedDB request is not a committed transaction.** Capture request results, but resolve write operations on transaction `complete` and reject on `abort`, with a fallback error because an explicit abort can leave `transaction.error` null. A commit-time failure need not produce a request `error` event. Attach transaction listeners before scheduling requests. Keep related metadata/transcript mutations in one transaction. Requests must be queued while the transaction is active: synchronously during creation or from its request callbacks. Do not insert unrelated asynchronous work such as timers or network requests between dependent cursor/read/write operations. [W3C transaction lifecycle](https://w3c.github.io/IndexedDB/#transaction-lifecycle), [abort algorithm](https://w3c.github.io/IndexedDB/#abort-transaction).

**Use fake-indexeddb 6.2.6 as a dev-only test adapter.** The official latest release is dated **16 October 2026**; its package declares Node **>=18**, ESM/CommonJS exports, TypeScript types and no runtime dependencies. The proposed exact pin is `pnpm add -D --save-exact fake-indexeddb@6.2.6` from `frontend/`; this research did not execute it. Import the adapter only in tests and reset with a fresh `IDBFactory`. Its implementation models abort rollback, making it more meaningful than mocks that immediately fire request success. Bun compatibility should be established by the focused suite rather than inferred from its Node requirement. [Release](https://github.com/dumbmatter/fakeIndexedDB/releases/tag/v6.2.6), [package declaration](https://raw.githubusercontent.com/dumbmatter/fakeIndexedDB/master/package.json), [transaction implementation](https://raw.githubusercontent.com/dumbmatter/fakeIndexedDB/master/src/FDBTransaction.ts).

Prioritize service tests for request-success-then-abort, rollback across both stores, cursor cleanup, concurrent open calls, and failed-open-then-retry. A rejected cached initialization promise must not permanently poison later attempts. Run these through the existing isolated `pnpm test` workflow. The adapter keeps data in memory; upstream's Web Platform Tests comparison documents incomplete browser conformance. Retain real-browser checks for event-loop timing, blocked upgrades, quota and persistence rather than treating adapter success as proof of disk durability. [Adapter isolation and coverage](https://github.com/dumbmatter/fakeIndexedDB#readme).

Both official OpenAI articles above were rechecked for this pass. The recommended Astra workflow remains evidence-led, with these narrow regression cases supplying the evidence; no scanner run or completed application fix is claimed here.

## 19 October follow-up: reachability beyond export and clone reports

The official [Astra maintenance article](https://developers.openai.com/blog/maintaining-software-with-the-gpt-6-family) and [prompting guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) were opened again for this pass. They support gathering deletion evidence, preserving indirect uses and operational safeguards, and defining completion explicitly. They do not establish that a clean scanner report proves unused code is absent.

- **Trace class methods to live callers.** Reuse the installed TypeScript language service: `findReferences(fileName, position)` supplies symbol references, while `provideCallHierarchyIncomingCalls` helps inspect callers. Build the service with the complete project context, including aliases and tests. Our proposed incremental check is to classify references inside other candidate methods separately from live entry points: mutually calling dead methods otherwise keep each other looking used. Preserve callback references, interface/override contracts and computed-property uses; a call hierarchy alone misses non-call references. Report test-only callers separately and verify candidates through the normal typecheck and affected behavior tests before removal. [Language-service context](https://github.com/microsoft/TypeScript/wiki/Using-the-Language-Service-API), [reference and call-hierarchy APIs](https://github.com/microsoft/TypeScript/blob/v5.8.3/src/services/types.ts#L607-L617).
- **Narrow Rust implementation visibility before trusting dead-code coverage.** `dead_code` examines unused, unexported items; `unreachable_pub` does not flag a deliberately exported but unnecessary API. For an implementation boundary already verified to have no external consumers, reduce visibility to the narrowest required scope and rerun the existing compiler checks across its supported consumers/configurations. This is a review technique, not a blanket rewrite. Keep `pub use`, generated dispatch, binary consumers and integration tests in the inventory. Also inspect supposedly unread fields before deletion: drop behavior and auto-trait properties can make an unread field meaningful. [Dead-code limitations](https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html#dead-code), [visibility scopes](https://doc.rust-lang.org/reference/visibility-and-privacy.html#pubin-path-pubcrate-pubsuper-and-pubself).
- **Add an advisory Python function report.** Vulture **2.16**, released **25 March 2026**, is a 27 kB wheel requiring Python **>=3.9**; its only runtime dependency is conditional `tomli` below Python 3.11. Pass a reviewed list of maintained Python files to `python3 -m vulture --min-confidence 60 --sort-by-size`. A threshold of 100 excludes function/method candidates. Keep this advisory: Vulture ignores scopes when matching names, so unrelated same-name uses hide candidates; dynamic callbacks can appear unused. Compare production and test references, review explicit whitelist entries, then rerun after confirmed deletions to reveal newly unreferenced helpers. Exit code 3 means findings. [Pinned release](https://pypi.org/project/vulture/2.16/), [package requirements](https://github.com/jendrikseipp/vulture/blob/v2.16/pyproject.toml), [analysis and confidence rules](https://github.com/jendrikseipp/vulture/blob/v2.16/README.md).
- **Extend structural review to duplicated fragments.** The earlier whole-function AST grouping misses common sequences within otherwise different functions. A bounded extension can compare contiguous statement windows using `ast.dump(..., include_attributes=False)`, retaining names and constants and reporting only substantial matches. This is our proposed heuristic, not a semantic-equivalence guarantee: compare free-variable binding, early exits and cleanup scopes before extraction. Keep the existing token baseline and caller-specific behavior assertions. [AST representation](https://docs.python.org/3.12/library/ast.html#ast.dump).
