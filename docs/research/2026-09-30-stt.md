# Local speech recognition as of 30 September 2026

Research cutoff: **2026-09-30**. Scope: private desktop meeting transcription, multilingual coverage, live latency, accurate reprocessing, licensing, and implementation in this repository. This is a primary-source review, not a benchmark run on local hardware. Links below identify manufacturer claims; no universal accuracy winner is asserted.

## Recommendation

Keep **Parakeet TDT v3 INT8** as Sonefold's small, native default for its 25 European languages. Add **Qwen3-ASR 1.7B** as an optional local accuracy/broader-language reprocessing engine, with **0.6B** as a smaller alternative. Pair Qwen with its forced aligner only for its supported alignment languages. Keep Whisper for unsupported languages and as a measured baseline. For live speaker recognition, benchmark **Nemotron 3.5 ASR Streaming 0.6B + Nemotron-3 Diarization**, or **Multitalker Parakeet** for English overlap. Both need persistent RNNT and speaker caches rather than the existing TDT/VAD decode interface. These choices balance integration risk, coverage, and quality; they are engineering recommendations inferred from the sources below.

WDER counts wrongly attributed **words**; it is not DER and cannot be compared directly with a diarization system's time-based DER. Its speaker numbers follow first appearance, not real-world identity. [Granite Plus evaluation](https://huggingface.co/ibm-granite/granite-speech-4.1-2b-plus#evaluations).

The [Open ASR Leaderboard paper](https://arxiv.org/abs/2510.06961) explains shared normalization and accuracy/efficiency tracks. FLEURS read speech is particularly different from overlapping, distant microphones. An [independent April 2026 streaming study](https://arxiv.org/abs/2604.14493) evaluates >50 configurations and identifies Nemotron streaming as its strongest compact English candidate; this supports prioritizing a benchmark, not copying its hardware-specific speed to this laptop.

## Runtime, alignment, and memory decisions

Qwen's [official inference API](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_asr.py) returns `ASRTranscription(language, text, time_stamps)`. `Qwen3ASRModel.from_pretrained(..., max_inference_batch_size=1, max_new_tokens=1024)` provides a straightforward single-user worker. `transcribe(audio=local_path, language=None)` detects language; canonical names such as `German` force it. Accurate times use `Qwen3-ForcedAligner-0.6B`; either request built-in timestamps or call the aligner's `align(audio, text, language)` after detected-language validation, as this worker does. Returned words expose `text`, `start_time`, `end_time`. Unsupported or invalid alignment falls back to visibly approximate chunk intervals, preserving transcription and absolute offsets.

The [Qwen technical report](https://arxiv.org/abs/2601.21337) covers multilingual/noisy speech and alignment evaluations. Code-switching support is a candidate property to test: detection of different languages across chunks does not guarantee accurate within-word or rapid-switch alignment. Qwen's June native Transformers conversion is also available, but has a separate checkpoint/API; never pass an `*-hf` checkpoint into a loader expecting the original package layout.

Weight-only estimates at BF16 are ~1.2 GB for 0.6B, ~3.4 GB for 1.7B, and ~8 GB for 4B. **These are arithmetic lower bounds, not VRAM requirements.** Audio activations, generation caches, alignment, framework overhead, and simultaneous summary/diarization models add memory. Start with batch one and bounded windows; unload one large model before loading another. A laptop RTX 5090 is not the H100/A100 used in throughput claims. [faster-whisper's reference measurements](https://github.com/SYSTRAN/faster-whisper#benchmark) explicitly use a 3070 Ti and show batching increases VRAM; no quoted multiplier should become a UI promise.

Use an optional isolated Python worker for NeMo/Qwen/Granite. Preserve the native Rust ONNX path for a lightweight install. [NVIDIA's native NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp) now supports Parakeet and Nemotron GGUF, while [parakeet-rs](https://github.com/altunenes/parakeet-rs) offers ONNX interfaces; these are viable future native integrations, not evidence that the existing `encoder-model.int8.onnx` TDT files support RNNT caches or LLM decoding.

NVIDIA's [Nemotron-3 ASR integration guide](https://huggingface.co/nvidia/Nemotron-3-Diarization/blob/main/ASR_INTEGRATION_GUIDE.md) couples the September 2026 diarizer to persistent `SpeakerTaggedASR` sessions. Multitalker Parakeet injects speaker targets; Nemotron 3.5 uses masked per-speaker audio streams. Ordinary Qwen transcript/turn alignment cannot recover two speakers' words from a mixed overlap. The implemented optional streaming adapter retains decoder/speaker caches and pending PCM across calls, reading structured SegLST records. Responses are cumulative revision snapshots that clients must upsert. NeMo examples replaying a WAV simulate streaming; live capture must supply PCM continuously. Recent NeMo Speech helpers and checkpoint revisions must be pinned together; a PyPI runtime alone may not include them.

Official Hub metadata/history verified the original Qwen revisions `7278e1e70fe206f11671096ffdd38061171dd6e5` (1.7B) and `c7cbfc2048c462b0d63a45797104fc9db3ad62b7` (aligner), both 2026-01-30. [ASR history](https://huggingface.co/Qwen/Qwen3-ASR-1.7B/commits/main), [aligner history](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B/commits/main). These original checkpoints fit `qwen-asr==0.0.6`; later native Transformers conversions use a separate environment/API.

## Repository findings and implementable changes

Inspection before implementation found:

- `frontend/src-tauri/src/parakeet_engine/model.rs` forces `CPUExecutionProvider`, even when Whisper is built with CUDA. CUDA Whisper builds therefore do not accelerate Parakeet.
- `TimestampedResult` already contains token emission times, but `ParakeetEngine::transcribe_audio` returns only text. Preserve token/word times with absolute recording offsets; token emissions alone are not independently aligned word ends.
- The provider warns about every language hint. V3 detects supported languages automatically; v2 is English only. Validate unsupported languages and explain automatic detection without claiming selectable language prompts.
- Frontend advertises an FP32 model absent from the Rust download catalog, includes M4 speed claims, and treats v2 as a generic small model. Align the catalog and replace unmeasured speed multipliers with capabilities.
- The existing native INT8 artifacts come from a community conversion, not the original NVIDIA checkpoint. Pin immutable revisions/checksums and measure conversion parity before claiming official accuracy.

Implementation order: preserve timing/correct metadata; add an offline stdio worker with validated local paths, bounded inference, cached model loading and structured errors; align speaker turns using word overlap; then benchmark an optional true-streaming Nemotron adapter. Record recordings/transcripts as private local data, not source-control fixtures.

## Native artifact provenance and integrity

The v3 INT8 catalog now uses the independently hosted [istupakov conversion pinned to `8f23f0c03c8761650bdb5b40aaf3e40d2c15f1ce`](https://huggingface.co/istupakov/parakeet-tdt-0.6b-v3-onnx/tree/8f23f0c03c8761650bdb5b40aaf3e40d2c15f1ce), dated 2026-02-17. Its four self-contained artifacts match the native loader's filenames and exact byte counts. The [conversion configuration](https://huggingface.co/istupakov/parakeet-tdt-0.6b-v3-onnx/blob/8f23f0c03c8761650bdb5b40aaf3e40d2c15f1ce/config.json) specifies a NeMo Conformer TDT, 128 input features, and subsampling factor 8. The tokenizer contains 8,193 indexed rows, ending with blank token 8,192. No FP32 external data file is required for this INT8 catalog.

ONNX digests come from primary [Hub LFS metadata](https://huggingface.co/api/models/istupakov/parakeet-tdt-0.6b-v3-onnx?blobs=true); the tokenizer digest was computed from its pinned contents. CDN ETags are not these content hashes. Downloads hash the retained prefix and streamed suffix, remove mismatches, and rename staged `.part` files only after verification. Explicit download retries also verify complete cached files. Routine model discovery uses exact sizes, avoiding repeated hashing of 670 MB; it does not detect subsequent same-size tampering. V2 retains its existing size-only contract. Matching artifact metadata establishes loader-contract compatibility, not inference parity or NVIDIA model-card accuracy. Preserve conversion and original-model attribution under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

## Reproducible selection benchmark

1. Freeze model revision, conversion revision, runtime lockfile, decoder parameters, chunk/VAD settings and normalization. Include Whisper large-v3, turbo, current Parakeet INT8, Qwen 0.6B/1.7B and at least one Granite candidate.
2. Evaluate consenting local meeting recordings stratified by English/German and required languages, accents, code-switching, remote/system versus microphone audio, quiet/noisy/far-field speech, overlap, silence/music, names/acronyms and 60–120 minute duration. Hold out whole meetings/speakers from tuning.
3. Report per-language and per-condition WER/CER, entity recall, deletion/hallucination rate on silence, punctuation accuracy, and confidence intervals by resampling whole meetings. Report cpWER or speaker-attributed WER plus DER/JER separately for diarization.
4. For timing, compare word boundaries with human labels, report median/p95 absolute boundary error and percentage within 200 ms. For live mode report first partial, stable word and final endpoint p50/p95 latency; hold allowed lookahead constant across models.
5. Measure cold start, model download/install size, peak RAM/VRAM, real-time factor, temperature/power and desktop responsiveness. Single-utterance and batched server throughput are separate measurements.
6. When the GPU also drives the desktop, run heavy local GPU evaluations under a GPU-sharing launcher ([GPU notes](../GPU_ACCELERATION.md#sharing-the-gpu-with-the-desktop)). No GPU benchmark was performed for this review.

The later real [CPU](stt-evidence/real-cpu-smoke.json) and [CUDA](stt-evidence/real-gpu-smoke.json) smoke checks use pinned original Qwen 1.7B plus aligner weights and synthetic English/German speech. Both transcriptions exactly match the generated text, with valid positive word spans and no worker alignment warnings. CUDA passed on an RTX 5090 Laptop GPU with Torch 2.14.0+cu130 and driver 615.71.09, under a GPU-sharing launcher at 85% of GPU threads. This verifies Qwen adapter/alignment and GPU compatibility on that hardware. Meeting accuracy, human-labelled boundary accuracy, throughput, and peak VRAM remain unmeasured. A separate [pinned NeMo CPU/CUDA adapter smoke](2026-09-30-diarization-evidence.json) subsequently validated Nemotron streaming on Torch/Torchaudio 2.7.1+cu128; English and longer German synthetic inputs produced speaker-tagged text, while the short German input returned no segments. That result establishes runtime compatibility with a documented omission risk, not multilingual meeting quality. Pyannote GPU compatibility remains unvalidated.

## Research method and evidence limits

Searches combined official organization/model names with release, license, timestamps, streaming, and multilingual terms. Followed model-card references to technical reports, runtime repositories, and the Open ASR evaluation framework. Screened candidates for meeting relevance, commercial local use, pre-cutoff release evidence, and implementable interfaces. Future or unverifiable releases and third-party ranking summaries were excluded. Manufacturer cards are primary evidence for interface/intent; they remain self-reported evidence for accuracy. Evidence inventory and screening scores are in `stt-evidence/papers-reviewed.json`; dependency-light tests cover runtime contracts and real Qwen smoke checks establish CPU/CUDA compatibility. Model quality and other runtime/GPU combinations require the benchmark above.
